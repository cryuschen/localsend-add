# LocalSend 右键设备子菜单

这是基于官方 CLI 的本地改造版本。文件管理器里选中文件或文件夹，打开右键菜单的 **LocalSend** 子菜单，再点击目标设备即可提交后台发送任务。

## 菜单内刷新

当前版本为 `1.18.2-local-unified.4`，采用事件触发的设备发现：

- CLI 启动时发送一次组播公告；空闲时只监听并响应其他设备，不进行周期扫描或主动测活，仍可接收文件。
- 打开普通右键菜单只读取本机缓存，不启动 CLI、不触发网络发现。真正展开 LocalSend 子菜单时，如果 CLI 已运行，立即公告一次并确认所有已知设备；不限于白名单设备。
- 进入 LocalSend 子菜单后的前十秒，未在线设备最早在上一轮检测完成一秒后重试，十秒到期后未在线设备恢复五秒间隔，菜单轮询不会延长加速窗口。设备一旦确认在线，本次菜单内保留确认结果，不再周期检测，也不再按六秒自动过期；重新进入菜单或点击刷新时重新确认。单轮连接上限仍为一秒，保持 HTTPS 证书指纹核对。菜单关闭后停止周期检测；文件管理器异常退出时，两秒租约到期也会停止新检查。已经开始的检测最多一秒结束。
- 菜单每 400 毫秒读取本机控制接口，让结果及时显示；这个频率不等于网络检测频率。后台 `devices` 控制请求为纯快照读取。
- 点击“刷新设备列表”后，转圈和动态设备按钮仍在原子菜单内，主动公告并探测已配对地址，必要时扫描最多三个 `/24` 网段的默认 53317 端口；已知设备保留自己的端口。整轮主动查找最多四秒，到时取消实际扫描并恢复刷新按钮。检测未找到设备时仍接收被动上线公告，展开菜单的五秒检测继续；不自动反复扫描整个网段。
- CLI 未运行时，点击设备发送、刷新或管理操作时才按需启动；启动后保持运行，直到手动停止。菜单中已配对设备可点击启动并发送。

同名设备按证书指纹区分。后台发送复用已验证可达的地址，避免误选失效的 IPv6 地址。菜单内的在线标记表示本次已确认过可连接；设备随后离线不会自动更新标记，点击发送时仍通过实际连接和 TLS 证书验证决定是否成功。可手动刷新或重新进入菜单重新确认。组播受限、手机休眠或 iOS 挂起时可能需要打开手机 LocalSend 后刷新。当前策略没有额外配置登录自启动。

设备菜单只显示已确认在线设备，以及已配对设备。重新进入菜单或刷新后，未确认在线的未配对设备隐藏；已配对设备仍保留并提示未连接。过滤同时作用于原地更新菜单与普通菜单，不删除白名单或后台发现记录。

菜单结果更新会先绘制已返回的状态，再处理排队的读取请求，避免本机读取稍慢时一直保留旧的“正在确认”标签。

本机 Nautilus 50.2 的实现使用 GTK `PopoverMenu.add_child` 在现有 LocalSend 菜单页中嵌入控件，并跟踪 Nautilus 每次右键重建菜单。其他文件管理器或不兼容版本仍保留普通菜单项，不保证支持原地转圈。手机端请保持 LocalSend 打开并连接同一局域网。

## 使用

```bash
localsend                 # 手动启动后台进程；已运行时复用
localsend devices --json  # 显式查找并等待结果，约四秒内输出设备列表
localsend status         # 查看运行状态、队列和最近任务
localsend stop           # 空闲时退出；传输中会提示等待
localsend stop --force   # 取消任务并退出
localsend send --to "设备名" "/path/to/folder"
```

终端发送可以使用设备别名或证书指纹；菜单始终使用设备指纹，避免同名设备混淆。后台发送复用最近连接检测成功的地址，避免检测时 IPv4 可达、发送却选中另一条失效 IPv6 路径。
历史 `-f "/完整路径/文件"` 写法仍可使用，它会在终端显示设备选择列表。
旧全屏终端的独立收发模式已弃用。`localsend terminal` 仅作为兼容入口启动或连接同一后台并立即返回，不再启动第二套网络服务。

未加入白名单的接收请求在 GNOME 顶栏显示接收、拒绝按钮；终端的 `localsend accept`、`localsend decline` 仍可使用。收到请求后四秒没有处理会自动拒绝并隐藏确认按钮，圆环保持原状。
已配对设备继续按已有规则自动接收。

## 旧终端功能迁移

| 原终端操作 | 统一后台后的入口 |
| --- | --- |
| D 设备列表 | 右键 LocalSend 菜单；`localsend devices --json` |
| 1–9 选择设备 | 展开有文件选择的 LocalSend 菜单后按 1–9；菜单外不占用数字键 |
| P 配对/取消配对 | 菜单“白名单管理”；`localsend pair DEVICE` / `localsend unpair DEVICE` |
| Y/N 接收/拒绝 | 顶栏按钮；`localsend accept` / `localsend decline` |
| P 接收并配对 | `localsend accept --pair`；普通顶栏接收仍只允许本次 |
| 终端文件/目录选择器 | 文件管理器选中项目后右键发送；`localsend send --to DEVICE PATH...`；历史 `-f` 仍可用 |
| Ctrl+C 取消活动 | 菜单“取消当前传输”；`localsend cancel`，同时取消排队发送，后台继续运行 |
| W+S 浏览器分享 | 菜单“通过浏览器分享所选项目”；`localsend web share PATH...` |
| W+R 浏览器上传 | 菜单“开启浏览器上传”；`localsend web receive` |
| 链接/二维码和停止分享 | 菜单“查看/关闭浏览器链接”；`localsend web status` / `localsend web stop` |

白名单、传输任务和链接状态只由同一个后台管理。无文件选择时，文件夹空白处的 LocalSend 菜单仍可管理白名单和浏览器接收，数字发送不会响应。数字编号在本次菜单打开期间固定；设备下线不会将它的号码让给其他设备，防止发送到错误目标。白名单操作使用唯一设备指纹，并且保存失败时不会在内存里留下未保存的信任变更。

菜单已移除底部的“1–9：发送到对应设备；白名单可在下方管理”提示文字，数字快捷键和白名单管理仍保留。上述功能也可通过终端命令操作；`localsend send PATH...` 不指定目标时，会列出设备并提示输入编号。

链接功能沿用原 CLI 实现：浏览器模式使用 HTTP，启用时明确提示未加密，关闭后恢复 HTTPS；普通收发、待确认或发送排队期间禁止切换，以免重启监听服务打断任务。原 LocalSend 协议、TLS 验证、校验、文件重名/保存规则均未改动。关闭用于输入命令的终端不停止后台；停止服务用 `localsend stop`，不需要页面内 quit。

## 按需启动规则

- 不设置开机或登录自启动。
- 仅打开普通右键菜单不会启动 CLI；已配对设备可直接列出。
- 点击设备发送，、点击“刷新设备列表”或执行显式管理操作，会在需要时启动 CLI。
- 启动后一直运行，直到手动执行停止命令或退出登录。
- 设备发现异步执行，不在 Nautilus 主线程中运行网络或传输任务。

后台日志：`~/.config/localsend-cli/background.log`。
本地控制套接字：`~/.config/localsend-cli/control.sock`，权限为 0600，同时核对连接者 UID。
独占锁保证并发启动请求最终复用同一后台进程。

## 功能边界

- 文件夹递归发送其中的文件，并在协议文件名中携带相对目录。空文件夹不发送，这是上游协议按文件传输的既有行为。
- 上游 CLI 接收端会将文件夹里的文件平铺到接收目录，并清理不合法字符；本次没有更改该规则。手机接收后的目录展现需在手机端确认。
- CLI 运行时，未确认在线的设备禁止点击发送；CLI 未运行时，已配对设备可点击启动并发送，找不到时通知失败。
- 发送任务会排队；顶栏通过常驻圆环显示真实进度和结果，结果五秒后逆时针恢复绿色。最近 20 项任务结果可通过状态命令查看。
- 收发系统通知已移除；收发成功后的圆环单击无操作；传输中单击取消，红色结果可单击提前恢复。详见 [顶栏扩展说明](../gnome/README.zh-CN.md)。

## 安装与重载

使用 `cargo build --release --locked --package localsend-cli --jobs 2` 编译。
将 `target/release/localsend-cli` 安装到 `~/.local/bin/localsend-cli`，并保留 `localsend` 指向它的链接。
将 `localsend_menu.py` 安装到 `~/.local/share/nautilus-python/extensions/`。
系统依赖为 `python3-nautilus`、`gir1.2-nautilus-4.1`；顶栏另需 GNOME Shell 50 和 GJS。

升级前如仍有旧版独立终端，应先结束其传输并自行退出。安装扩展后，保存正在进行的文件操作，关闭并重新启动 Nautilus，或退出登录后重新登录，才会加载菜单扩展。
